# 馆藏数据与金匮导览

数据来自用户提供的《皇史宬馆藏档案整理清单.xlsx》及《编号及图例.pptx》。原附件未修改。

- 清单第 3–33 行，共 31 份档案，保留八列原文、单元格超链接和来源行号。
- 按固定随机种子 `20261010` 分配至 31 个不同金匮：主殿 25 份、西殿 6 份。刷新页面不会重新分配。
- 两张平面图中的已编号柜体均可点击：主殿 133 个、西殿 35 个。未分配档案的柜体明确显示“暂无档案”。
- 随机位置仅用于数字展示，清单中的现存地点和散佚说明保留原文；不将展示位置视为历史事实。

## 三维建筑

`public/models/huangshicheng.glb` 为用户于 2026-10-19 提供的《皇史宬2.glb》，保留原始文件内容，通过 GLTFLoader 加载。该文件只包含一座殿宇，因此三座建筑使用同一模型：主殿保持长宽高比例，东西殿等比例缩小并旋转朝向院内。保留原模型材质、现有院落布局、建筑点击入口和东殿关闭规则。

## 数据维护

`src/data/collection.json` 保存完整清单、柜体矩形、通道、障碍和分配结果。`scripts/import-archives.py` 使用 openpyxl 只读入原工作簿，生成这份 JSON：

```sh
python scripts/import-archives.py "/path/to/皇史宬馆藏档案整理清单.xlsx"
npm test
npm run build
```

导入器中柜体坐标已按原图校准，坐标原点为图片左上角；两图尺寸均为 1448 × 1086。新增或移动金匮时应同步调整通道及障碍，重新执行可达性测试。

## 寻路与交互

点击柜体显示档案信息；面板中的“寻路”显示朱色路线。检索档案名称、档案编号或金匮编号后点击结果，会切换到对应殿宇、选中金匮并自动寻路。尚未到达金匮时从入口出发，路线成功后记录柜旁终点为当前位置；下一次寻路从该位置出发。只查看档案不改变位置，失败、取消或过期的请求不会更新位置。“清除路线”保留当前位置，“回到入口”清除路线并重置位置。各殿独立保存当前位置；可用“选择起点”在通道设置新位置。

时间轴初始不高亮。拖动或用方向键调整年份后，仅在该年有年代匹配档案的金匮周围显示金色光晕、向上散开的光束与浮动星芒；未匹配、空金匮和未知年代记录保持原图样式。光效随金匮缩放且不拦截点击，系统开启减少动态效果时使用静态光晕。点击金匮和寻路不触发额外光效，切换殿宇沿用所选年份，“清除高亮”移除全部光效。匹配只影响金匮外观，完整档案仍可点击和检索，所有柜体继续作为寻路障碍。

`src/data/archiveTime.ts` 保存按清单“所属年代”换算的公元年区间，包含区间两端。明确的编修年份仅匹配该年，明确的编修起讫按区间匹配，只有朝代的记录使用整个朝代范围，未换算的年代不参与高亮。清单《太祖实录》中的“乾隆初”未写明起止年，暂只匹配该条明确的顺治十二年，不自行估算“初”的年份。面板显示每条记录实际采用的区间与依据。这些范围用于年代检索，不表示实物在金匮内的实际存放年限。

纪年换算参考[故宫博物院宫廷世系](https://www.dpm.org.cn/court/lineages.html)。按公元年粒度计入清帝退位发生的 1912 年，参考[故宫博物院宣统皇帝介绍](https://www.dpm.org.cn/court/lineage/226255.html)。

网页实际调用原版 `path_engine/AStar.cpp`：`nativeNavigation.ts` → `POST /api/navigation/path` → `NavigationController` → `NativePathProvider.findPath` → JNI → C++ A*。前端生成新平面图的 4 像素网格，将墙体、展柜、未编号金色柜及所有编号柜体设为障碍，柜体周围保留 3 像素间距。后端使用原版四方向 A* 和曼哈顿距离，分别计算柜旁可行走候选终点，选择最短的一条。前后端接口坐标为网格索引，显示时转回原图像素。路线只合并共线点，不用斜线跨越柜角。没有实体比例尺，因此不显示虚构的米数或步行时长。

点击平面图上的“寻路”后点金匮，或在阅档面板点击“寻路”，即可显示朱色路线。每次请求冻结出发位置，成功后的到达位置只用于下一次寻路，避免自动重算当前路线。切换终点、起点或殿宇时会取消旧请求。寻路、查看档案和调整窗口大小均保持当前缩放比例；仅主动点击缩放或“复位”才改变画面比例。缩放按钮使用较小步长和 Leaflet 动画，滚轮、触摸缩放及金匮光效同步。服务不可用时显示错误和“重新规划”按钮，不替换成前端算法。`pathfinding.ts` 中的 JavaScript A* 仅作为回归测试的参考解，不参与网页实际寻路。

在 `frontend` 运行 `npm run dev:full` 可自动编译原版动态库、启动 Spring Boot 的 `navigation` 配置和 Vite；已有可用后端时复用它。该配置仅监听本机 18080，无需 MySQL；原项目的其他配置不变。原 CMake 构建方式继续可用，Mac/Linux 也可运行 `sh path_engine/build-native.sh`。生产环境必须保留后端，并将 `/api` 转发到它；仅托管 `dist` 无法调用原版引擎。

`npm test` 检查档案唯一性、柜号唯一性、网格与参考路径、点击检索状态、连续寻路的当前位置与出发点、过期请求、入口重置和时间轴规则，以及原版引擎接口的坐标换算、错误处理和无静默降级。后端启动后，`npm run test:native` 经真实 HTTP/JNI/C++ 链路验证全部 168 个柜体从入口可达、避障且最短，并验证从上一个金匮继续寻路、自选起点、无路和错误请求。项目根目录执行 `sh path_engine/build-native.sh` 后运行 `./mvnw test`，检查真实原版引擎、JNI 输入检查、接口参数和 Spring 上下文。
